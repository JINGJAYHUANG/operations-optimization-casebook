# Operations Optimization Casebook 中文说明

这是一个把运筹优化从“求最优值”推进到“形成可审计决策”的公开案例库。

## 核心判断顺序

```text
问题定义
→ 数据与约束合同
→ 可行性
→ 精确参考求解
→ 独立复算
→ 与现状基准比较
→ 压力测试
→ 实施责任与门禁
→ 推荐 / 条件执行 / 暂停
```

系统明确区分：

```text
模型求解成功
≠ 模型完整
≠ 输入正确
≠ 现实可以立即执行
```

## 十类公开案例

- 生产组合与资源分配；
- 工厂到配送中心的运输分配；
- 技术人员与任务指派；
- 设施选址与客户分配；
- 多时段人员排班；
- 不确定需求下的单周期库存；
- 项目关键路径与赶工；
- 小规模车辆路径；
- 多情景鲁棒选择；
- 资本项目组合。

公开数据全部为合成数据，不对应真实企业、工厂、客户、员工、车辆或投资项目。

## 三种决策状态

### `recommended`

数学结果、审计、基准、压力规则、责任人和实施门禁都满足，且没有待审批条件。

### `conditional`

最优解本身成立，但仍需要人工审批、对压力情景敏感，或存在尚未关闭的运营条件。

### `hold`

发生硬失败，例如：不可行、目标函数复算不一致、服务水平不足、最大后悔值超限、压力情景不可行、缺少实施负责人或最优性证明不成立。

任何“节省金额”都不能覆盖 Hold。

## 参考求解器边界

项目中的求解器是透明、无第三方依赖的小规模精确参考实现。它们适合：

- 教学；
- 模型审计；
- 回归测试；
- 生产求解器结果复核；
- 小型离散决策。

它们不追求大型工业模型性能。真实问题应接入成熟求解器，同时保留相同的输入、可行性、目标复算、压力测试和证据合同。

## 运行

```bash
python -m pip install -e .

opcase run-suite \
  --manifest examples/synthetic-suite/casebook.json \
  --output run-reference \
  --fixed-time 2026-09-02T00:00:00Z

opcase verify --run-dir run-reference --deep
```

## 最重要的使用原则

不要把求解器输出直接发给执行团队。先检查：

1. 约束是否完整；
2. 基准方案是否真实；
3. 目标函数是否包含全部重要成本；
4. 输入变化时方案是否稳定；
5. 是否有负责人、监控指标和回退条件；
6. 是否需要人工审批；
7. 是否存在模型没有覆盖的现实限制。
